## Tasks

1. **Cursor-tie fix** (`libs/db/src/events.ts` → `listUpcomingEvents`).
   - Today: `WHERE startsAt > after ORDER BY startsAt` — **two events sharing a `startsAt` make the
     cursor skip the second.** Infinite scroll exposes this immediately.
   - Fix: `ORDER BY startsAt, id` + composite cursor. Accept `{ afterStartsAt?: number; afterId?: string }`

# P1-008 — RSVP flow + atomic D1 capacity

**Branch off merged P1-007a.** Owns RSVP end-to-end + the real `<RsvpSection>` + attendance
population. Implements FR-E3/E4, §11.5.

## Tasks

1. **Migration `0005_*.sql` + schema:**
   - `event_rsvps` table: `id` (pk), `event_id → events` (cascade), `user_id → user` (cascade),
     `status` enum `['going','waitlist','cancelled']`, `created_at`, `updated_at`,
     **`UNIQUE(event_id, user_id)`** (one RSVP per user per event).
   - **Denormalized counter** on `events`: `rsvps integer notNull default 0` (drives the atomic
     capacity check — see `libs/db/src/atomic.ts`). Kept in sync with `event_rsvps` via `db.batch()`.
   - Generate via `drizzle-kit generate`.
2. **`libs/db/src/rsvps.ts`** (NEW): `createRsvp`, `cancelRsvp`, `listRsvpsForEvent`, `countGoing`.
   - **Atomic capacity** (`db.batch()` — D1 has no interactive transactions):
     `UPDATE events SET rsvps = rsvps + 1 WHERE id = ? AND rsvps < capacity` **in the same batch as**
     the `INSERT INTO event_rsvps`. If the `UPDATE` affected 0 rows → event is full → `waitlist`
     (or `event_full` error if no waitlist). Never read→decide→write across awaits (TOCTOU).
   - `cancelRsvp`: batch `UPDATE event_rsvps SET status='cancelled'` + `UPDATE events SET rsvps = rsvps - 1 WHERE id = ? AND rsvps > 0`.
3. **`libs/server-fns/src/rsvps/`** (NEW: `resolver.ts` + `rpc.ts` + `index.ts`, exported from main barrel):
   - `createRsvp` rpc: authed (`requireAuth`), Zod-validated, `requirePermission('rsvp','create')`.
     Returns `{ status: 'going' | 'waitlist' }` or throws `event_full`.
   - `cancelRsvp` rpc: authed.
   - `getMyRsvps` rpc: authed (for the user's "my events" — used later by dashboard P1-016).
   - **RBAC:** add the `rsvp` resource and grant `member` `rsvp: ['create','read','update']` in
     `libs/auth/src/rbac.ts` (mirrors the P1-006 `event:create` grant). Use the CRUD verb **`update`**,
     not a domain verb `cancel` — it matches better-auth's native `defaultStatements` verb set and the
     existing `event:create`/`event:read` pattern; `cancelRsvp` checks `rsvp:update`. **Cancel is also
     ownership-gated** (`rsvp.userId === session.user.id`): RBAC says *members may update RSVPs*;
     ownership says *only your own*.
4. **Populate attendance** (`attendance.ts` + `events/rpc.ts`):
   - `attachAttendance(db, events, viewerId?)` — **no N+1, no per-event COUNT:**
     - `goingCount` = the denormalized **`event.rsvps` counter** (already on the row for the atomic
       capacity check — free, zero extra queries).
     - `remaining = capacity === 0 ? null : capacity - event.rsvps`.
     - `viewerRsvp` = **one** grouped query for the whole list:
       `SELECT event_id, status FROM event_rsvps WHERE user_id = ? AND event_id IN (?,?,…)`, mapped back
       onto events. (Skipped entirely when `viewerId` is null / logged-out.)
   - Wrap the `getEvent` + `getUpcomingEvents` **rpc handlers** to attach attendance (resolver stays
     untouched — contract §3).
   - **Narrow `EventWithAttendance`** from `Event & Partial<EventAttendance>` → `Event & EventAttendance`
     (required). P1-007a's conditional UI now always renders the attendance block — exactly the plan.
5. **Real `<RsvpSection>`** (`apps/ui/src/components/RsvpSection.tsx`): props unchanged (contract §2).
   - "I'm attending" button → `createRsvp` with **optimistic UI** (TanStack Query mutation; rollback
     on error). Shows `remaining` (FR-E4); full → waitlist CTA; already going → "Cancel" via `cancelRsvp`.
   - Logged-out → button links to `/login?redirect=<detail>`.
6. **Notifications — out of scope (FR-E8 = P1-009).** P1-008 ships RSVP + capacity with **no**
   notification wiring. The RSVP-confirmation enqueue is P1-009's deliverable; **P1-009 adds the enqueue
   call into the `createRsvp` mutation** when its queue producer lands. Do **not** stub, fake, or leave a
   `TODO` for it here — AGENTS.md §1 forbids placeholders; an unbuilt dependency means the work is simply
   not done yet, never faked.
7. **Out of scope:** anti-no-show commitment (FR-E10) = **P1-010**; host RSVP dashboard = **P1-016**.
